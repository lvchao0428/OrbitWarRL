## 1. Day8 给出的稳定事实

### 1.1 已经可以当作“定理”的结论

| 现象 | 证据 | 含义 |
|---|---|---|
| **再加 src/target 特征也不够** | `f35` 的 `garr` 升到 `68-80`，但 `spf` 仍只有 `6-7`，`WLD` 仍 `0/5` | 瓶颈不再主要是“看不懂源星/目标星” |
| **策略被锁在单路 emit attractor** | `u199/u299` 都是 `n1=98.8%`、`e2+=0%` | 问题在 **turn-level 动作结构**，不是单个 head 的局部数值 |
| **1-ship trickle 仍大量存在** | `one_ship_rate ≈ 35%`，`min_game_spf ≈ 1.2` | reward 罚 1-ship 不足以改变策略生成方式 |
| **训练 log 仍会误导** | `f35` 在 `@399` 后 `spf/garr` 快速膨胀，但 replay 决策早在 `@199/@299` 就已 fail | checkpoint 选择必须继续依赖 replay |
| **self-play collapse 提前出现** | `@349` 还勉强可看，`@399` 已从 `spf 58` 跳到 `213` | Day9 不能再跑长训后才评估 |

### 1.2 Day9 的问题定义

Day9 要解决的核心问题，不再是“多给模型一点源星/目标星信息”，而是让策略真正学会这三件事：

1. **有些回合不发**：把 `z0` 从 `<1%` 拉到一个健康区间，而不是几乎回合回合都发。
2. **该发时能连续发 2-3 手**：把 `e2+` 从 `0%` 拉起来，打破 `n1≈99%`。
3. **发的是更大的舰队**：让 `spf` 和 `flip` 一起上升，而不是继续靠 `bin7=100%` 从小星球挤 1-3 艘。

## 2. Day9 的总体策略

### 2.1 原则

1. **不再优先做新特征工程**
   - Day8 已说明：即使 `src-quality + target_score 蒸馏 + anti-1-ship reward` 一起上，也没有把策略从坏 attractor 里拉出来。

2. **每次只改一个系统层面变量**
   - Day9 明确拆成两条支线：
   - `f36a` 只动 **动作机制**
   - `f36b` 只动 **训练分布**
   - 不再一上来做大杂烩组合拳。

3. **短训 + 密 replay**
   - `@350-400` 已反复证明是危险区。
   - Day9 默认 run 长度 **<= 350 upd**，checkpoint 更密，优先看早期 replay。

4. **replay 指标比训练指标更高优先级**
   - `WR vs random/frozen` 只能当健康度参考，不能作为 promote 依据。

### 2.2 基线锁定

Day9 默认锁定以下基线，避免变量过多：

| 项 | 锁定值 |
|---|---|
| 提交基线 | `f29 @599` |
| 观测方向 | **不新增特征**，优先回到 pre-f35 的稳定观测栈 |
| PPO | 继续沿用 `f33/f35` 的稳定配方：`lr=3e-5`, `clip=0.20`, `ppo_epochs=1`, `vf=0.5` |
| 训练长度 | `<= 350 upd` |
| 评估方式 | `replay vs v20` only |

## 3. 路线三的两条支线

### 3.1 `f36a` — 动作机制 delta only

**目标**：优先打破 `n1≈99% / e2+=0% / z0<1%` 这个 turn-level attractor。

**要改的方向**：

1. **放松或改写 `emit_worth_it` 一次发完就停的闸门**
   - 当前证据很强：模型经常只做一次 emit，然后回合结束。
   - Day9 要让策略在“存在多个可打弱点 / 存在安全 surplus”时，能够继续做第 2、3 次发兵决策。

2. **把“多路 emit”变成可学目标，而不是偶发副产物**
   - 不是盲目鼓励 `emit=8`，而是让 `emit=2~3` 在合适局面里有正向梯度。
   - 重点是提高 `e2+`，不是追求无脑多发。

3. **不碰观测特征，不碰大模型，不碰大 entropy sweep**
   - 这一条必须保持纯净，确保我们知道变化来自动作机制本身。

**预期改善信号**：

- `e2+`：`0% -> >3%`
- `z0`：`<1% -> >3%`
- `spf`：`6-7 -> >8`
- `flip`：`3-4% -> >4.5%`
- `one_ship_rate`：`35% -> <25%`

**失败信号**：

- `bin0` 重新炸到 `>15%`
- `e8` 重新回弹到 `>5%`
- `e2+` 仍接近 `0`
- `one_ship_rate` 无明显下降

### 3.2 `f36b` — 训练分布 delta only

**目标**：不改动作机制，只验证问题是否主要来自训练生态把策略推回坏 attractor。

**要改的方向**：

1. **引入强对手锚定**
   - 用 `f29 @599` 或同等 replay 强者作为固定强对手，避免纯 frozen/self-play 把分布卷回去。

2. **缩短 run，提前 checkpoint 选择**
   - 不再默认“训满再看”。
   - 重点比较 `@199/@249/@299/@349` 的 replay，而不是晚期 checkpoint。

3. **训练目标从“更强 self-play”改为“更接近 v20 对战分布”**
   - 只要 replay 指标更接近 v20，哪怕 random/frozen WR 平平，也优先保留。

**预期改善信号**：

- 训练 `spf/garr` 不再在 `@350-400` 附近跳变
- replay 指标更单调
- `@299` 左右出现比 `f35` 更好的 `spf/flip/e2+`

**失败信号**：

- 仍在 `@350-400` 提前 collapse
- replay 相比 `f35` 几乎不动
- 仍然 `n1≈99%`

### 3.3 `f36c` — 组合分支（后置）

只有当 `f36a` 或 `f36b` **单独** 出现正向信号时，才允许进入组合：

- `f36c = best(action mechanism) + best(training distribution)`

Day9 不允许反过来先做 `f36c`。

## 4. 评估协议（Day9 强制执行）

### 4.1 训练长度与 checkpoint

默认 checkpoint 观察点：

```bash
149 / 199 / 249 / 299 / 349
```

不再把 `599/799` 当默认主评点。

### 4.2 replay gate

每个候选 ckpt 都看 `first-80` 指标：

| 指标 | Day9 route alive | Day9 promote 参考 |
|---|---|---|
| `bin0` | `<15%` | `<15%` |
| `e8` | `<5%` | `<5%` |
| `z0` | `>3%` | `>8%` |
| `e2+` | `>3%` | `>5%` |
| `spf` | `>8` | `>10` |
| `flip` | `>4.5%` | `>6%` |
| `one_ship_rate` | `<25%` | `<20%` |
| `min_game_spf` | `>3` | `>5` |
| `WLD` | 可先 `0/5`，但必须看到多指标改善 | `>=1/5` |

### 4.3 继续 / 终止规则

**继续某条分支** 的最低条件：

- `spf`、`flip`、`e2+`、`one_ship_rate` 至少 **3 项** 有实质改善；
- 同时 `bin0/e8` 不退化。

**直接终止某条分支** 的条件：

- 到 `@299` 仍 `WLD 0/5`，且动作指标几乎不动；
- 或者 `bin0/e8` 明显恶化；
- 或者训练 log 再次出现 `@350-400` 附近的膨胀跳变。

## 5. Day9 执行顺序

1. **先做 `f36a`**
   - 只动动作机制。
   - 训练到 `@349`。
   - replay `149/199/249/299/349`。

2. **若 `f36a` 无明显动作指标改善，则停**
   - 不因为“也许再训久一点会好”而续训。

3. **再做 `f36b`**
   - 只动训练分布。
   - 同样用短训 + 密 replay。

4. **仅当 `f36a` 或 `f36b` 有正向信号时，才允许 `f36c`**
   - Day9 不做无依据组合拳。

---

## 6. 明确不做的事

1. **不再优先扩观测特征**
   - Day8 的 `f35` 已经给出足够反证。

2. **不再跑长训再事后找最优 checkpoint**
   - 这会再次把时间浪费在 collapse 后区域。

3. **不再根据 `WR vs random/frozen` 做 promote 决策**
   - 这些指标只能做训练健康度参考。

4. **不做多个系统改动同时上线**
   - 必须保持因果清晰。

---

## 7. Day9 期望产出

Day9 结束时，希望至少得到以下之一：

1. **一个 route alive 的 `f36a` 或 `f36b`**
   - 虽然还没赢 v20，但已经明显摆脱 `n1≈99% / e2+=0% / one_ship≈35%`。

2. **一个明确的负结论**
   - 能证明“动作机制”还是“训练分布”哪个更可能是主因，避免 Day10 继续盲试。

3. **若出现 `WLD >= 1/5` 的 ckpt**
   - 才进入提交候选讨论。
